OpenClaw AI Agents Guidebook

A practical step-by-step handbook for designing, building, testing, and deploying AI agents and chatbots in OpenClaw, based on the agents and chatbot projects already built in this workspace.

This guide is grounded in four real reference patterns:

  • 1-Group AI Research Scout: an internal research and briefing agent built natively in OpenClaw
  • 1-Group Marketing AI Tutor: a training and daily co-pilot agent built natively in OpenClaw
  • 1-Group Culinary Agent: a specialist domain agent for chefs and kitchen operations built natively in OpenClaw
  • Gojo / Max chatbot projects: custom website chatbots built outside native OpenClaw channels, with OpenClaw used as the design and development environment

The goal of this handbook is simple: give you a repeatable operating method for developing and deploying useful AI agents in OpenClaw without falling into generic prompt sludge, weak scope control, or messy deployment.

1. What OpenClaw Is

OpenClaw is an agent runtime and gateway system. It is not just a chat UI.

In practice, OpenClaw combines:

  • A workspace: the files that define how the agent behaves
  • A gateway: the always-on service that runs the agent and handles channels
  • Channels: the surfaces where users interact with the agent, such as webchat, Telegram, WhatsApp, Discord, and others
  • Sessions: conversation state and routing context
  • Tools: capabilities such as file access, browser control, web search, messaging, cron, and node/device integration
  • Automation: heartbeat rules and cron jobs for recurring work

The quality of the agent depends heavily on the quality of its workspace design.

2. The Two Main Build Paths

Path A: Native OpenClaw Agent

Use this when the agent will run directly inside OpenClaw and reply through OpenClaw channels.

Examples from your builds: Research Scout, Marketing AI Tutor, Culinary Agent.

Best for internal assistants, research agents, operational copilots, training bots, staff-facing specialists, and recurring briefing agents.

Path B: External Website Chatbot

Use this when the chatbot lives on a custom website or app, and OpenClaw is mainly being used as the design environment, coding environment, or systems thinking framework.

Examples from your builds: Gojo chatbot and Max's anime site chat widget.

3. Start With Agent Design, Not Config

Every strong agent you have built so far started with a clear concept before any deployment work.

  • Purpose: what the agent exists to do
  • Audience: who it serves
  • Scope: what it covers and what it does not cover
  • Personality: how it should sound
  • Boundaries: what it must never do
  • Success metric: how you will know it is working

Example: Research Scout

  • Purpose: research and assess AI tools
  • Audience: 1-Group digital transformation / innovation team
  • Scope: practical AI tools across business functions
  • Boundaries: no hype, no commitments, no pretending committee decisions happened in chat
  • Success metric: useful daily briefings and credible evaluations that the team actually uses

Example: Marketing AI Tutor

  • Purpose: training companion plus daily marketing co-pilot
  • Audience: marketing team, managers, and team leads
  • Scope: content, prompts, tool guidance, quizzes, scenario practice, ops coordination
  • Boundaries: no budgets, no ready-to-post claims, no cross-venue strategy leakage
  • Success metric: daily usage, better content output, faster AI skill uptake
